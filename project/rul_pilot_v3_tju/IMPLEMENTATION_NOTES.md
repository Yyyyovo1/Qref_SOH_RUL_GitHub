## 澄清

1. **数据集名称：** 为 `NCA` 和 `NCM`，与冻结输出一致。
2. **检查 0：** 用冻结的 TJU v2 数据重新计算 t₀,₁、t₀,₂、t₀,₃，要求与方案 §2 的冻结值完全一致。
3. **检查 1：** 正式运行产生的严格规则状态、首次到达循环和容差规则类型，与 `reruns/tju_label_structure/2_labels_per_cell_setting.csv`（随方案提交）逐行一致。容差规则使用 `protocol_validation.endpoint.tolerance_rule`。
4. **检查 4：** 在 v2 的基础上另加一项：每个设置中，除余量特征外的设计矩阵，等于按 (电芯, t) 从共用特征表取出的行。共用特征表与 Q_ref 无关，因此这一项保证了方案 §3.2 中"三种 Q_ref 下逐字节相同"的要求。共用特征表的 SHA-256 写在检查结果中。
5. **静态特征：**
   - `Temperature_C` 取文件名中的温度；
   - `Charge_CRate` 取文件名中的充电倍率，例如 `025` 表示 0.25C；
   - 两者都来自冻结的 `tju_cell_inventory.csv`，直接作为数值列，不取水平值和斜率。
   - 在同一训练折内取值恒定时，WAFT 按 v2 规则去掉这一列。
6. **反转与比较：**
   - 受支持的反转使用 v2 的 `find_reversals`。
   - 一次比较"可估计"，指两个设置下该方法对的配对区间都可估计（`pair_ci.Estimable`）。
   - 反转率 = 可估计比较中受支持的反转数 ÷ 可估计比较数。
7. **P1 的分段：**
   - 较低的有标签比例 r = min（两个设置的严格规则精确终点比例），分母为该数据集的全部电芯。
   - A 段：0.30 ≤ r < 0.60；B 段：0.60 ≤ r < 0.90。
   - 检查 5 未通过的数据集不进入 P1 的合并计算；两个数据集都未通过时，P1 记为"无法检验"。
8. **去重事件（§5.3）：** 按 (数据集, θ, 方法对, Q_ref 两两比较) 归并三个评价集。任一评价集可估计，即为一个可估计事件；任一评价集上出现可估计的受支持反转，即为一个反转事件。
9. **按机制拆分（§5.3）：** 对 nominal 与实测参考的比较，按哪一侧的严格规则比例较低，标为 `nominal_lower` 或 `measured_lower`。
10. **容差规则的分段：** 只作对照。比例取自标签结构参考文件中的容差规则类型，反转不重新计算。
11. **开发运行模式（`--dev`）：** 在检查 0–4 和方法可估计性之后停止，不做 bootstrap，不计算任何区间、比较或反转。只有开发运行允许使用 θ 或数据集子集。
12. **输出目录：** 已存在时拒绝覆盖，与 v2 相同。
